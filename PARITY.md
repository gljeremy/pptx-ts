# pptx-ts ↔ python-pptx parity

Port of [python-pptx](https://github.com/scanny/python-pptx) at commit `278b47b`
(v1.0.2, 2024-08-06).

## Behavioral differences

1. **Lengths are numbers** (EMU). `Inches()`, `Pt()`, `Cm()`, `Mm()`, `Emu()`,
   `Centipoints()` return numbers; use `new Length(x).inches` etc. to convert.
2. **One number type**: integer validation is `Number.isInteger`, so `1.0` counts as an int,
   and booleans are not numbers.
3. **Files**: anything that takes a file accepts bytes (`Uint8Array`/`ArrayBuffer`), a
   file-like object with `read()`/`write()` (e.g. the exported `BytesIO`), or — in Node — a
   path. Browsers have no paths.
4. **Mappings**: python-style collections (`_Relationships`, readers) expose `get(k)`
   (raising `KeyError` like `obj[k]`), `has(k)` for `in`, `length` for `len()`, and iterate
   their keys.
5. **Exceptions**: `ValueError`, `KeyError`, `IndexError`, `AttributeError`,
   `NotImplementedError` are exported classes; JS `TypeError` stands in for python's.
6. **Zip output** is written by fflate (deflate level 6, like python's zipfile); archives
   differ byte-wise from python's but contain identical members.
7. **Indexed access** to sequences is `.at(idx)` (python `slides[idx]`, negative indexes
   work), because several collections already have a `get()` with another meaning
   (`slides.get(slideId)`, `slide.placeholders.get(idx)` for python's
   `slide.placeholders[idx]`, `layoutPlaceholders.get(idx)`).
8. **Enum members** are `Number` objects (python int enums), so compare members with `===`
   and convert with `+member` or `.value`; `String(member)` is python's `str()`
   (`"TITLE (1)"`). `PROG_ID` members are objects with `progId`, `iconFilename`, `width`,
   `height`.
9. **Dates**: python's naive `datetime` values are `Date`s holding the wall-clock time in UTC
   (read with `getUTC*()`); core-property dates are written from those UTC fields.
10. **`Presentation()` with no argument** opens the default template from bytes bundled in the
    library (python opens `pptx/templates/default.pptx` from disk). The OLE-object icons are
    bundled the same way.
11. **Images**: format, pixel size and DPI come from the image headers rather than Pillow,
    matching Pillow 11.0's values (including its quirks: a JPEG JFIF density counts only when
    its unit is dots per inch; WMF and most EMF files report a single dpi value, which
    python-pptx ignores in favor of 72). Formats
    Pillow opens but python-pptx rejects (WEBP, ICO, PSD, ICNS, EPS) give python-pptx's
    "unsupported image format" `ValueError`; anything else raises `UnidentifiedImageError`.
12. **Line spacing**: python tells a `Length` (points) from a float (lines) with
    `isinstance`; here an integer of at least 1000 EMU, or a `Length` object, is a length and
    anything smaller or fractional is a multiple of lines.
13. **`fitText()`** measures text from the font file (`src/text/ttf.ts`) instead of Pillow's
    FreeType rendering; it accepts a font path (Node) or the font file's bytes (browsers).
    Font discovery by family name also searches Linux font directories (python-pptx raises
    `OSError` there). Like python-pptx, a word wider than the box makes it raise.
14. **Chart workbooks**: python-pptx writes the workbook embedded in each chart with
    XlsxWriter; pptx-ts has its own writer (`src/xlsx/workbook.ts`) for the calls python-pptx
    makes on a single worksheet named `Sheet1`. For ordinary chart data, the XML matches
    XlsxWriter 3.2 except for timestamps in `docProps/core.xml` (the zip container bytes also
    differ). Worksheet numbers use Python-compatible `%.16G` formatting with ties-to-even
    rounding. XlsxWriter's `write()` turns a string starting with
    `=` into a formula, a URL-like string into a hyperlink, and `<r>...</r>` into raw rich
    text; pptx-ts writes all of these as plain text (a category named `=Revenue` would
    otherwise show as `#NAME?` in Excel, and a `<r>` label could make the workbook invalid).
15. **Integral floats in chart XML**: python writes a float value as `11.0` and an int as
    `11`; JS has one number type, so `11.0` is written `11`. PowerPoint and Excel read both
    the same. Non-integral values (`1.1`, `1e-05`) are written exactly as python writes them.
16. **Dates in chart data** are UTC `Date`s (item 9). Like python-pptx, chart category caches
    discard the time of day, while the embedded workbook retains it as a fractional day.
    The workbook follows XlsxWriter's 1900-01-01 special case for non-midnight datetimes;
    a midnight `Date` is treated as Python's `date`, not a midnight `datetime`.
17. **Chart collections**: `chart.plots.at(i)`, `plot.series.at(i)`, `series.points.at(i)` and
    `plot.categories.at(i)` are python's `[i]`; `chart.plots.slice(start, end)` is
    `plots[start:end]`. A `Category` is a `String` object, so `String(category)` and
    `` `${category}` `` give its label.
